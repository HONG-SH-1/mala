# ADR-004: 평가 대상을 docs 고정 사본으로

| 항목 | 내용 |
|------|------|
| **상태** | Accepted |
| **날짜** | 2026-10-29 |
| **맥락** | 0단계 기준선을 잴 노트 묶음이 필요함 |

---

## 맥락

기준선은 이후 바꾸는 것마다 같은 조건으로 다시 재서 비교하는 기준이다. 그러려면 검색 대상이 바뀌지 않아야 하고, 질문과 결과를 레포에 남길 수 있어야 한다.

- 개인 Obsidian 볼트는 계속 바뀐다. 내용도 공개할 수 없어 질문과 결과를 git에 올릴 수 없다.
- 레포 `docs/`는 공개 문서지만, 작업하면서 계속 고친다 (이 ADR도 `docs/`에 들어간다).

## 결정

- 2e55c5b 시점의 `docs/`를 `data/eval_corpus/docs-20261028/`로 복사해 평가 대상으로 고정한다 (`.md` 20개).
- 색인, 컬렉션, manifest는 평가 전용으로 따로 쓴다. 설정은 `eval/env_docs.ps1`에 모은다. `.env`와 기존 볼트 색인은 건드리지 않는다.
- 질문(`eval/questions.yaml`)과 결과(`eval/results/`)는 공개 docs 기준이라 git에 올린다.
- `data/`는 git 밖이라 사본 자체는 올라가지 않는다. 다른 PC에서는 2e55c5b의 `docs/`에서 다시 복사한다.

## 근거

| 옵션 | 장점 | 단점 |
|------|------|------|
| 개인 볼트 | 실제 사용 상황과 같음 | 계속 바뀜, 질문과 결과를 공개 못 함 |
| 지금의 `docs/` | 공개 가능 | 커밋마다 바뀌어 비교가 흔들림 |
| **docs 고정 사본 (채택)** | 안 바뀜, 공개 가능, 커밋으로 다시 만들 수 있음 | 실제 볼트와 내용, 크기가 다름 |

## 결과

- 사본, 질문, 설정 스크립트 중 하나라도 바꾸면 새 기준선이다. 질문의 출처나 판정만 바뀐 경우는 `eval_rescore`로 다시 채점한다.
- 문서가 프로젝트 자신에 대한 글이라, 여기서 좋아진 것이 개인 볼트에서도 좋아진다는 보장은 없다.
- 기준선 결과 파일(`eval/results/20261028-2205_baseline-docs.md`)에 찍힌 커밋 b138a0b는 push 전 커밋 메시지를 바꾸기 전 해시다. 내용은 a266ae5와 같다.
