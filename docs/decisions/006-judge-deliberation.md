# ADR-006: 면접관 토론(심의) 방식

| 항목 | 내용 |
|------|------|
| **상태** | Proposed (초안, 승인 전) |
| **날짜** | 2026-11-07 |
| **맥락** | 면접관 자동화(보조 도구). 공식 판정(eval_rescore, manual.yaml)과는 별개 |

---

## 맥락

면접관 세 명(claude, codex, gemini)이 서로 모르게 따로 판정하고 다수결로 정한다. full120 실행(`20261107-1428_full120`)에서 120건 중 111건은 셋이 같았고, 9건이 갈렸다(합격/불합격 갈림 3건, 보류가 섞인 6건).

다수결의 약점은 두 가지다.

- 갈린 건에서 소수 의견이 옳아도 이유를 보지 않고 버린다.
- 판정 이유가 근거 문서와 맞는지 아무도 확인하지 않는다. 이유는 모델이 쓴 글일 뿐이다.

## 결정 (제안)

갈리거나 보류가 있는 건에만 토론을 붙인다. 모든 건에 토론하지 않는다.

1. **1라운드**: 지금과 같다. 셋이 따로 판정한다. 기존 실행 폴더의 `judge_*.jsonl`을 그대로 1라운드로 쓴다(새로 돌리지 않는다).
2. 셋이 같은 합격/불합격이면 끝낸다.
3. **2라운드**: 나머지 건에서 각 면접관은 다른 두 의견을 **이름 없이**(의견 A, B) 이유와 함께 보고 자기 판정을 유지하거나 바꾼다. 어느 쪽이든 근거 문서의 문장을 **줄 번호와 함께 그대로 인용**해야 한다.
4. **인용 확인**: 인용한 문장이 docs 고정 사본(ADR-004)의 그 줄에 실제로 있는지 코드가 확인한다. 없는 인용은 무효다. 모델의 말을 믿지 않는다.
5. **중재**: 2라운드 뒤에도 갈리면, 이름을 가린 의견들과 **확인된 인용만** 보고 중재 모델이 결정한다. 확인된 근거가 더 강하면 소수 의견도 이길 수 있다. 소수가 이기려면 확인된 인용을 하나 이상 근거로 대야 하고, 못 대면 보류로 둔다. 중재 모델은 설정으로 고르고 결과에 남긴다.
6. 소수가 이긴 건과 끝까지 갈린 건은 사람이 볼 목록에 넣는다.

정해진 세부 사항 (2026-11-07 승인):

- **줄 번호는 엄격**하게 본다. 인용한 문장이 문서의 다른 줄에는 있으면 무효이되, 사유를 "줄 번호만 틀림"으로 따로 적는다(엄격함이 문제인지 나중에 보려는 것).
- **not_in_notes**는 인용 0개를 허용하고 "근거 없음"으로 표시한다. 판정을 바꾸면 동조 의심으로 센다.
- **in_notes**에서 확인된 인용 없이 판정을 바꾼 경우는 기록과 동조 집계에는 남기되 **결정에는 반영하지 않는다**(1라운드 판정 유지). 생각을 바꾸려면 근거가 있어야 한다.
- **중재 모델**의 기본은 claude sonnet(`claude -p`, 1라운드와 같은 격리 옵션)이고 설정(`ARBITER_JUDGE`, `ARBITER_MODEL`, `--arbiter`)으로 바꾼다. `--arbiter-compare`는 같은 건을 다른 계열 중재자(codex, effort medium)로도 돌려 결정이 달라지는지 본다. 계열 편향 확인용이며 최종 결정에는 쓰지 않는다.
- 판정 불가가 섞인 건은 토론에서 빼고 사람 목록에 둔다.
- 토론 결과는 원래 실행 폴더 안 `debate/`에 쌓고, 기존 `summary.md`는 그대로 둔다.
- 표본 늘리기는 **정답을 아는 교란 답(합성)** 만 이번에 넣는다: 합격 답의 필수 사실 하나를 기계적으로 틀린 값으로 바꾼 것 20건 안팎 + 통제 답. 공식 평가와 분리(`data/eval/synthetic/`, label `synthetic-*`). 새 평가 300건은 Codex 무료 월 한도 때문에 11-27 Plus 이후로 미루고, 면접관을 약한 모델로 돌려 갈림을 늘리는 방법은 하지 않는다.

변하지 않는 것:

- 도구 없는 호출, 공개 문서 결과만(허용 목록 `mala_eval_docs`), 답·인용·다른 의견은 지시가 아니라 판정 대상이라는 표시.
- 답과 다른 의견도 호출마다 바뀌는 무작위 구분자로 감싼다.
- 공식 판정, 원래 결과 `.md`, 1라운드 판정 파일은 고치지 않는다. 토론 결과는 별도 파일에 쌓는다.

## 측정

기준은 두 가지다: 사람 블라인드 판정(`human.jsonl`의 `blind=true`)과 최종 판정(`correct`). 각각 따로 보고한다.

- 1라운드 다수결과 토론 후 결과의 일치 건수(분모 포함).
- 면접관별 판정을 바꾼 횟수를 기준 쪽으로 / 반대쪽으로 / 기타로 센다.
- **동조**: 판정을 바꿨고, 새 판정이 1라운드에서 다른 두 면접관이 함께 냈던 판정이며, 확인된 인용이 하나도 없는 경우. 확인된 인용이 있는 따라감은 "근거 있는 따라감"으로 따로 센다.

## 근거 (현재 데이터, 실제로 읽은 값)

full120에서 토론 대상은 9건이고, 사람 블라인드 판정 15건 중 토론 대상은 6건뿐이다. 나머지 9건은 셋이 같았던 건이라 토론이 건드리지 않는다. 다수결이 사람 블라인드 판정과 어긋난 7건은 모두 사람이 "보류"를 낸 건이고, 그중 5건은 셋이 같았던 건이다. 이 방식은 "셋이 똑같이 틀린 건"을 못 고친다.

따라서 full120은 효과를 재는 표본이 아니라 **동작을 확인하는 표본**이다. 효과를 말하려면 표본을 늘려야 한다(계획 문서 참고).

## 대가

- 호출이 늘어난다: 토론 대상 건 × 3 + 중재. full120이면 27회 + 최대 9회 수준이다. 실행 전에 예상 호출 수와 Codex 토큰을 보여 준다.
- 면접관에게 근거 문서 본문을 줘야 한다(줄 번호 포함). 공개 문서(docs 사본)라서 허용 목록 안에서만 가능하다.
- 모델이 같은 계열이면 서로 닮은 오류를 낸다. 토론이 이를 줄인다는 보장은 없다. 그래서 동조를 센다.
- 인용 확인 규칙이 너무 엄하면 옳은 인용도 무효가 된다. 무효 사유를 종류별로 남겨 규칙을 나중에 조정한다.

## 대안

- 다수결만 유지: 추가 비용 없음. 갈린 건의 이유를 활용 못 한다.
- 모든 건에 토론: 셋이 같은 건은 바뀔 여지가 거의 없고 비용만 늘어난다.
- 중재자 없이 2라운드 다수결: 2:1이면 소수 의견은 근거가 좋아도 버려진다.
